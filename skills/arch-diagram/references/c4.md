# C4 — context, container, component, deployment, dynamic

Simon Brown's C4 model, drawn in the house design system. Use when the
request says C4, or names a context / container / component / code
diagram. C4 is a set of zoom levels over one software system: each
diagram shows ONE level and every element on it carries its type.

## Levels → house recipes

| C4 view | Shows | Build on |
|---|---|---|
| L1 System context | the system in scope (one box), people, external systems | `system-context.md` layout, C4 anatomy below |
| L2 Container | inside the system boundary: apps, services, data stores | skeleton below |
| L3 Component | inside ONE container: components + the containers/externals they touch | skeleton below, boundary = the container |
| L4 Code | classes/tables | don't draw by hand; generate from code (UML/ERD tooling) |
| Deployment | containers mapped to infrastructure nodes per environment | `deployment.md`: frames = deployment nodes, container boxes inside |
| Dynamic | numbered interactions for one use case | `sequence.md`, or this skeleton with numbered labels ("1. Submits case [HTTPS]") |
| System landscape | several systems in an enterprise | L1 recipe with an enterprise boundary frame |

## Element anatomy

Every box carries three lines, centred:

1. **Name** — 11px 600 ink.
2. **[Type: technology]** — 8.5px muted: `[Person]`, `[Software System]`,
   `[Container: Node.js]`, `[Component: Spring Bean]`. L1 elements carry
   type only; L2+ carry technology.
3. **Description** — 8.5px body, one or two lines (≤ ~26 chars each at
   160 wide): what it does, not what it is built with.

Shapes and colours (house tokens; override with the brand):

| Element | Shape | Fill / stroke |
|---|---|---|
| Person | head circle r11 above a body rect rx14, 160×70 | band-b `#eef2f7` / body `#475569` 1.3 |
| Software system in scope | rect rx6 (L1: large, 260–300 wide) | accent-fill `#f0fdfa` / accent `#0d9488` 1.6 |
| Container | rect rx6, 160×88 | accent-fill / accent 1.4 |
| Data-store container | cylinder (ellipse ry8 top + front arc) | accent-fill / accent 1.4 |
| Component | rect rx4, 150×76 | white / accent 1.2 |
| External system or person | same shape as its kind | `#f1f5f9` / frame `#94a3b8`, name in body colour (greyed) |
| Boundary | rect rx8, dashed `5 4`, no fill | accent for the system in scope; frame grey for an enterprise boundary |
| Deployment node | rect rx8 solid frame, nested | `deployment.md` frames |

Boundary label sits **bottom-left** inside the frame: name 10.5px 600 in
the boundary colour + `[Software System]` (or `[Container]`) 8.5px muted.
Children keep ≥12px clear of the boundary.

Optional icons (from `icons.svg`) may sit top-left in containers; the
type line still carries the technology, icons never replace it.

## Relationships

- One-directional arrow, house stroke 1.3, stop 2px short.
- Label in two lines beside or above the line: **verb phrase** 9px body
  ("Reads customers", "Makes API calls"), then **[technology]** 8.5px
  muted ("[REST/HTTPS]"). Halo (`stroke="#fff" stroke-width="3"
  paint-order="stroke"`) when a label crosses a boundary line.
- Direction = dependency or who initiates; say so in the key.
- Dynamic views prefix the verb with the step number.

## The C4 rules (check every diagram)

1. A title stating diagram type and scope: "Container diagram · Service Portal".
2. One level per diagram. No components on a container diagram.
3. Every element shows its type (and technology from L2 down).
4. Every element has a short description.
5. Every line is labelled with intent, and with technology from L2 down.
6. Every line is one-directional.
7. External elements are visually distinct (greyed) from the system in scope.
8. A key on every diagram: shapes, colours, boundary dash, arrow meaning.
9. Acronyms explained in the key or the description.

## Layout notes

- L1: system box centred, people left/top, externals right/bottom;
  6–7 relationships max.
- L3: the boundary is the container; components in a grid of 150×76;
  containers and externals they touch sit outside, drawn as at L2.
- Labels between columns need the gap to fit them: measure
  (0.52 × px × chars) and widen the gap before shortening the verb.
- Deployment: one diagram per environment; container boxes keep their
  L2 names so the views agree.

## Pitfalls

- A boundary edge through a relationship label: move the boundary or the
  column, not the label onto the line.
- Mixing levels "for completeness" — split instead.
- Technology-only labels ("HTTPS") — the verb is mandatory.
